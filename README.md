# ai-chat-demo-2

Веб-приложение для переписки с моделью. Пользователь регистрируется, входит и ведёт чаты. Ответ модели приходит потоком в Markdown. Заголовок чата появляется после первого успешного ответа.
Модель подключается через OpenAI-совместимый клиент. Адрес, ключ и имя модели задаются окружением и в репозиторий не зашиты.

Разработано в качестве тестового задания с применением AI-агента GROK BUILD
Исходный промпт в default-prompt.md, а итеративные изменения в /changes, при этом на каждый такой файл есть коммит с конкретными изменениями с агентом

## Стек

Бэкенд:

- Java 25, Gradle 9.8.2
- Spring Boot 4.1.2, Spring Security, Spring AI 2.0.1
- PostgreSQL 16, jOOQ, Liquibase
- JWT, springdoc, MapStruct

Фронтенд:

- React 19, Vite 7
- В полной сборке статику отдаёт nginx и проксирует `/api` на бэкенд

## Что понадобится

- Docker, чтобы поднять Postgres или всё приложение целиком.
- JDK 25, если бэкенд запускается через Gradle. Если в системе по умолчанию другая Java, укажите её в `JAVA_HOME`.
- Node.js 22 и npm, если фронтенд запускается отдельно в режиме разработки.
- Доступ к OpenAI-совместимому API: `AI_API_KEY`, `AI_BASE_URL`, `AI_MODEL`.

Для ответов модели нужны все три переменные. Если провайдер недоступен или отвечает ошибкой, интерфейс сообщает, что сервис ИИ недоступен, и сообщение не сохраняется.

## Переменные окружения

| Переменная | Зачем |
| --- | --- |
| `AI_API_KEY` | Ключ API модели |
| `AI_BASE_URL` | Базовый адрес OpenAI-совместимого API, например `https://host/v1` |
| `AI_MODEL` | Имя модели |
| `JWT_SECRET` | Секрет подписи JWT, не короче 32 байт |

Профиль по умолчанию — `local`. В нём, если `AI_API_KEY` и `JWT_SECRET` не заданы, подставляются локальные заглушки, и `./gradlew bootRun` может стартовать. `AI_BASE_URL` и `AI_MODEL` значений по умолчанию не имеют.

В `full-docker-compose.yaml` переменные пробрасываются из оболочки. Пустое значение с хоста попадает в контейнер как пустая строка. `JWT_SECRET`, если он не задан, в этом файле получает локальный секрет `local-dev-jwt-secret-change-me-32`.

Пример:

```bash
export AI_API_KEY="ключ"
export AI_BASE_URL="https://host/v1"
export AI_MODEL="имя-модели"
export JWT_SECRET="локальный-секрет-не-короче-32-байт"
```

## Запуск всего приложения

Одна команда поднимает Postgres, API и интерфейс:

```bash
docker compose -f full-docker-compose.yaml up --build
```

- Интерфейс: http://localhost:5173
- API: http://localhost:8080
- Swagger: http://localhost:8080/swagger-ui.html

База этой сборки не публикуется на порт хоста. Данные лежат в томе `aichat-full-pg`.

Остановка без удаления данных:

```bash
docker compose -f full-docker-compose.yaml down
```

## Локальный запуск для разработки

Postgres публикуется на порт `5432`. Этот порт должен быть свободен. База, пользователь и пароль — `aichat`. Данные лежат в томе `aichat-pg`, отдельно от полной сборки.

```bash
docker compose up -d
export JAVA_HOME=/path/to/jdk-25
./gradlew bootRun --no-daemon
```

Фронтенд в другом терминале. Vite проксирует `/api` на http://localhost:8080, поэтому отдельный CORS не нужен.

```bash
cd frontend
npm install
npm run dev
```

Интерфейс разработки: http://localhost:5173.

Тесты бэкенда:

```bash
export JAVA_HOME=/path/to/jdk-25
./gradlew test --no-daemon
```

## Бэкенд

Префикс API — `/api/v1`. Открыты регистрация, вход, Swagger и OpenAPI. Остальные ручки требуют `Authorization: Bearer <token>`. Отдельной ручки выхода нет: токен stateless.

Регистрация и вход:

- `POST /api/v1/auth/register` — логин, почта, пароль. Ответ `201` и JWT.
- `POST /api/v1/auth/login` — логин и пароль.
- `GET /api/v1/users/me` — профиль текущего пользователя.

Логин и почта хранятся в нижнем регистре и уникальны. Логин: 3–64 символа, латиница, цифры, точка, подчёркивание и дефис. Пароль: 8–72 символа. Почта не длиннее 255 символов. Повтор логина или почты отвечает `409`.

Чаты:

- `POST /api/v1/chats` — пустой чат.
- `GET /api/v1/chats` — страница чатов, новые сверху. `query` ищет по заголовку без учёта регистра, `cursor` и `limit` листают страницу.
- `GET /api/v1/chats/{chatId}` — чат и последняя страница сообщений. Курсор запрашивает более старые.
- `POST /api/v1/chats/{chatId}/messages` — сообщение и поток SSE.

События потока: `delta` с куском текста, `title` с заголовком, `done` с идентификаторами, `error` при сбое модели. Размер страницы по умолчанию 20, максимум 100. Сообщение не длиннее 16000 символов, заголовок не длиннее 120. В историю модели уходит до 40 последних сообщений. Чужой чат отвечает `404`. Время в ответах — UTC.

Если модель не ответила, сообщение пользователя удаляется. Сбой генерации заголовка не отменяет уже сохранённый ответ.

Ошибка имеет вид `{ "code", "message", "details" }`. Коды: `VALIDATION`, `LOGIN_TAKEN`, `EMAIL_TAKEN`, `UNAUTHORIZED`, `NOT_FOUND`, `TECHNICAL`. Тексты валидации на русском.

## Фронтенд

Интерфейс на русском.

- Регистрация, вход и выход. Выход стирает токен из `localStorage`.
- Список чатов, поиск по заголовку и кнопка «Ещё чаты».
- Открытие чата и подгрузка более ранних сообщений.
- Создание чата.
- Отправка сообщения и потоковый ответ. Текст бота рисуется как Markdown.
- Коды `LOGIN_TAKEN`, `EMAIL_TAKEN`, `UNAUTHORIZED`, `NOT_FOUND` и `TECHNICAL` показываются по-русски.
- Если модель недоступна, на экране текст «Сервис ИИ сейчас недоступен. Сообщение не сохранено.»
